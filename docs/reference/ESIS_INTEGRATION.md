# ESIS интеграци — бодит API-ийн тэмдэглэл

**Эх сурвалж:** <https://developer.esis.edu.mn/> (нээлттэй баримт бичиг,
2026-09-03-нд уншсан). Захиалагчийн өгсөн <https://developerv2.esis.edu.mn/>
нь нэвтрэлт шаарддаг SPA — `Нэвтрэлт шалгаж байна…` гэж зогсдог тул түүнээс
техникийн мэдээлэл авах боломжгүй. Доорхи бүх зүйл нээлттэй `developer.`
доменоос авсан.

> ★ Энэ баримт бичиг нь **уншсан зүйлээ бичсэн**, туршиж үзсэн зүйлээ биш.
> Бодит endpoint дуудагдаагүй — эрх байхгүй (§4). Аль хэсэг нь батлагдаагүйг
> §3-т тусад нь ялгасан.

---

## 1. Юу тодорхой болсон

| Зүйл            | Утга                                                           |
| --------------- | -------------------------------------------------------------- |
| Үндсэн URL      | `https://hub.esis.edu.mn/svc/api`                              |
| Нэвтрэлт        | **Bearer token**                                               |
| Токен авах      | `POST /login` — хэрэглэгчийн нэр, нууц үгээр                   |
| Бусад нэвтрэлт  | `POST /teacher/login`, `POST /student/login`                   |
| Хариуны бүрхүүл | `SUCCESS_CODE`, `RESPONSE_MESSAGE`, `RESULT`                   |
| 401 гэвэл       | "та өөрийн нэвтэрч буй хэрэглэгчийн нэр, нууц үгээ шалгана уу" |
| `/public/…`     | Бүрэн нэвтрэлтгүйгээр хандах боломжтой                         |

### 1.1 Цэцэрлэгт хамаарах endpoint

Сургуулийн өмнөх боловсролын хэсэгт **нэг** endpoint баримтжуулсан:

```
POST https://hub.esis.edu.mn/svc/capital/sub/students/active/list
Body: { "registerNumber": "..." }        # хүүхдийн регистр
```

Зорилго: _"Цэцэрлэгийн хүүхдийн мэдээлэл шалгах"_.

Хариу:

```json
{
  "SUCCESS_CODE": 200,
  "RESPONSE_MESSAGE": "Амжилттай хадгалагдлаа",
  "RESULT": { "status": 1, "message": "Амжилттай", "data": "…" }
}
```

★★ **Замын угтвар нь `/svc/capital/`, `/svc/api/` биш.** Энэ нь чухал: манай
`ESIS_BASE_URL` нэг үндсэн замыг л агуулдаг, харин ESIS-д дор хаяж хоёр өөр
угтвар байна. Endpoint нэмэхдээ энэ ялгааг барих ёстой.

### 1.2 Ерөнхий боловсролын endpoint-ууд

Цэцэрлэгт шууд хамаарахгүй ч ижил hub дээр байна — ирээдүйд хэрэг болж
магадгүй тул тэмдэглэв: `/hub/organization/info`, `/hub/group/list`,
`/hub/group/student/list/:studentGroupId`, `/hub/student/check/:personId`,
`/hub/student/movement/v2/:beginDate`, `/hub/teacher/list`,
`/public/lookup/:hubLookupType` гэх мэт.

## 2. Манай кодтой тулгасан нь — нэг бодит зөрүү

`apps/api/src/integrations/esis/` дэх хил хязгаар голдуу таарч байна:
Bearer token, timeout, redaction, лог, `isConfigured` — бүгд хэрэгтэй хэвээр.

**Гэхдээ нэвтрэлтийн загвар таарахгүй.**

|         | Манай код (одоо)                 | ESIS (бодит)                  |
| ------- | -------------------------------- | ----------------------------- |
| Токен   | `ESIS_TOKEN` — орчноос статикаар | `POST /login`-оос динамикаар  |
| Хугацаа | Тооцоогүй                        | Дуусдаг (401 → дахин нэвтрэх) |
| Нууц үг | Байхгүй                          | Шаардлагатай                  |

`EsisConfig.isConfigured` нь `baseUrl && token && institutionId` гэж шалгадаг.
Бодит байдалд `ESIS_USERNAME` + `ESIS_PASSWORD` хэрэгтэй бөгөөд токеныг
кодоороо авч, кэшлэж, дуусахад нь шинэчлэх ёстой.

★ **Энэ бол аль хэдийн шийдэгдсэн асуудал — энэ репод.** `QpayClient` яг ийм
загвартай: `getAccessToken()` нь кэшлэсэн токеныг буцаах эсвэл дахин нэвтэрч
авдаг, `TOKEN_SAFETY_MARGIN_MS` нь дуусахаас өмнө шинэчилдэг, `redact()` нь
нууц үг болон токеныг логоос хасдаг. ESIS-ийн нэвтрэлтийг бичихдээ түүнийг
загвар болгоно — шинээр зохиох шаардлагагүй.

★★ **Одоо засаагүй, зориудаар.** Нэвтрэлтийн хүсэлтийн яг талбарын нэр
(`username`/`password` уу, өөр үү), хариунд токен ямар талбарт ирэх, хугацаа
ямар нэрээр илэрхийлэгдэхийг нээлттэй баримт бичгээс **баталж чадаагүй**.
Тэдгээрийг таамаглаж бичих нь `esis.service.ts` өөрөө сэрэмжлүүлдэг алдаа
болно: _"нэг нь үүссэн даруйд дэлгэц түүн дээр баригдаж, таамаг тархана"_.

## 3. Батлагдаагүй зүйлс

- `POST /login`-ийн хүсэлтийн биеийн талбарын нэрс.
- Токен хариунд ямар талбарт ирэх, амьдрах хугацаа.
- `/svc/capital/…` endpoint-ууд ижил токен хүлээж авах эсэх.
- `RESULT.data` нь мөр үү, объект уу — жишээнд далдлагдсан байсан.
- Rate limit, дахин оролдох бодлого.
- Цэцэрлэгийн хувьд өөр endpoint байгаа эсэх (нээлттэй хэсэгт **ганц**
  л баримтжуулсан: хүүхдийн регистрээр шалгах).

## 4. Эрх авах — техникийн биш, гэрээний асуудал

Холболтын заавраас:

1. Хувийн хэвшлийн компани **Боловсрол, шинжлэх ухааны яамтай** мэдээлэл
   солилцох гэрээ байгуулна.
2. Яам түншлэгч боловсролын байгууллагуудын жагсаалтыг **Боловсролын
   мэдээллийн технологийн төв**-д хүргүүлнэ.
3. Төв нь тухайн компанид системийн мэдээлэл солилцох эрхийг үүсгэж,
   гэрээнд заасан мэдээллийг дамжуулна.

★ Өөрөөр хэлбэл **бүртгүүлэх маягт байхгүй** — энэ нь гэрээ, дараа нь
provisioning. Хөгжүүлэлтийн хугацааг төлөвлөхөд үүнийг тооцох ёстой: код
бэлэн болсон ч эрх хүлээх хугацаа тусдаа.

## 5. Дараагийн алхмууд, дарааллаараа

1. **Яамтай гэрээ** (§4). Бусад бүх зүйл үүнээс хамаарна.
2. Эрх авсны дараа `ESIS_BASE_URL`, `ESIS_USERNAME`, `ESIS_PASSWORD`,
   `ESIS_INSTITUTION_ID`-г тохируулах. `ESIS_TOKEN` нь орлуулагдана —
   `.env.example` болон `env.ts` засварлагдана.
3. `EsisClient`-д `getAccessToken()` нэмэх, `QpayClient`-ийн загвараар.
4. Sandbox дээр `POST /login`-ийг **нэг удаа** дуудаж, хүсэлт/хариуны яг
   бүтцийг тэмдэглэх. §3-ыг үүгээр солино.
5. Endpoint бүрд Zod схем, `request<T>()`-д `parse` болгон дамжуулах.
6. Цэцэрлэгийн endpoint-ыг **тусдаа, хянагдах өөрчлөлт** болгож нэмэх.
7. Ямар чиглэлд өгөгдөл урсахыг шийдэх — татах уу, илгээх үү. Энэ нь
   authorization болон аудитын шаардлагыг өөрчилнө (CLAUDE.md §1.1, §3.2).

## 6. Одоогийн байдлын үнэлгээ

> Хил хязгаар **бэлэн** — тохиргоо, timeout, redaction, лог, эрүүл мэндийн
> тайлан, 19 тест. Нэвтрэлтийн загвар **засвар шаардана** (статик токен →
> нэвтрэлтээр авах). Интеграци өөрөө **бүхэлдээ хийгдэх ёстой**, тэр нь
> гэрээ байгуулагдсаны дараа эхэлнэ.

Энэ баримт бичиг нь `esis.service.ts`-ийн "endpoint зохиохгүй" гэсэн байр
суурийг үгүйсгэхгүй — харин ч бататгаж байна: одоо бодит зам, бодит хариуны
бүрхүүл байгаа ч нэвтрэлтийн нарийвчлал дутуу хэвээр, тиймээс домэйн метод
бичих цаг болоогүй.
