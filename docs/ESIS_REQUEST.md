## Хавсралт 1 — Хүсэж буй мэдээлэл

Бүгд **зөвхөн унших**. Бичих (`POST`) сервис хүсэхгүй — ESIS дэх бүртгэлийг
манай систем өөрчлөхгүй.

Endpoint-ууд нь `developer.esis.edu.mn`-ий v1 баримт бичгээс. **v2 дээр нэр нь
өөрчлөгдсөн байж болзошгүй** тул хариу бичигт баталгаажуулна.

| #   | ESIS сервис                    | Endpoint (v1)                                         | Яагаад хэрэгтэй вэ                                                     | Манай хүснэгт                   |
| --- | ------------------------------ | ----------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------- |
| 1   | Байгууллагын ерөнхий мэдээлэл  | `GET /svc/api/hub/organization/info`                  | Цэцэрлэгийн албан ёсны нэр, хаяг, ангилал — гар оролтын алдааг арилгах | `kindergartens`                 |
| 2   | Хичээлийн жилийн статус        | `GET /svc/api/hub/academic/year/statuses`             | Хичээлийн жилийн эхлэх/дуусах огноог ESIS-тэй нэг мөр байлгах          | `school_years`                  |
| 3   | Бүлгийн жагсаалт               | `GET /svc/api/hub/group/list`                         | Бүлгийн нэр, насны түвшин                                              | `groups`                        |
| 4   | Бүлгийн суралцагчийн жагсаалт  | `GET /svc/api/hub/group/student/list/:studentGroupId` | Хүүхэд аль бүлэгт харьяалагдахыг тогтоох                               | `enrollments`                   |

### 1.1 Талбарын түвшний хүсэлт — хүүхэд (#5)

Хүүхдийн мэдээллийг **зөвхөн дараах талбараар** хүсэж байна:

| Талбар                              | Манай багана           | Тайлбар                                     |
| ----------------------------------- | ---------------------- | ------------------------------------------- |
| Овог                                | `children.lastName`    |                                             |
| Нэр                                 | `children.firstName`   |                                             |
| Төрсөн огноо                        | `children.dateOfBirth` | Насны бүлэг, өсөлтийн жишиг тооцоход        |
| Хүйс                                | `children.sex`         |                                             |
| Бүлэг (ID, нэр)                     | `enrollments.groupId`  |                                             |
| ~~Регистрийн дугаар~~               | `children.nationalId`  | **Хүсэхгүй** — ↓ доорх тэмдэглэгээг үзнэ үү |
| ESIS-ийн дотоод дугаар (`personId`) | _(шинэ хүснэгт)_       | Дахин тулгалтын түлхүүр                     |

★ **Регистрийн дугаар.** Манай схемд `children.nationalId` талбар байдаг бөгөөд
`@@unique([kindergartenId, nationalId])` буюу цэцэрлэг доторх давхардлыг
хориглодог. Гэхдээ ESIS-ээс РД татах эсэх нь **зөвхөн техникийн шийдвэр биш**:
Хүний хувийн мэдээлэл хамгаалах тухай хуулиар хүүхдийн мэдээллийг хууль ёсны
төлөөлөгчийн зөвшөөрөлтэйгээр, зорилгын хязгаартай боловсруулна.

Хоёр хувилбар:

- **(a)** РД-г татаж хадгална — тулгалт хамгийн найдвартай, гэхдээ нэмэлт
  хамгаалалт, зөвшөөрлийн бүртгэл, хадгалах хугацааны бодлого шаардана.
- **(b)** РД-г **огт татахгүй**, `personId`-аар тулгана — хувийн мэдээллийн
  ачаалал хамгийн бага. `personId` нь ESIS-ийн дотоод дугаар бөгөөд бидний
  талд өөрөө утга илэрхийлэхгүй.

**Энэ ноорог (b)-г сонгосон** — хүснэгтэд РД дарагдсан байгаа нь тийм учиртай.
`children.nationalId` талбар схемд байх боловч цэцэрлэг өөрөө гараар оруулах
эрхтэй хэвээр үлдэнэ; ESIS-ээс автоматаар дүүргэхгүй.

(a)-г сонговол хүснэгтийн зураасыг арилгаад, Хавсралт 2-т РД-д хамаарах хадгалах
хугацаа, устгах журмыг нэмэх ёстой. Гэрээний хавсралтаас талбар **хасах** нь
дараа нь **нэмэхээс** хамаагүй хялбар тул эргэлзвэл (b)-гээр эхэл.

### 1.2 Талбарын түвшний хүсэлт — багш, ажилтан (#7, #8)

Овог, нэр, албан тушаал, заах аргын нэгдэл, албан и-мэйл, ESIS `personId`.

**Хүсэхгүй:** цалин, боловсролын дэлгэрэнгүй түүх, ажлын туршлагын бүрэн бүртгэл,
гэрийн хаяг, РД. Багшийн данс үүсгэхэд эдгээр шаардлагагүй.

### 1.3 Хүсэхгүй байгаа зүйлс (зориуд)

Дүн, сурах бичиг, дүрэмт хувцас, сонгон судлах хичээл, цахим сургалтын модуль,
барилга/өрөөний бүртгэл, суралцагчийн өрхийн байдал, эрүүл мэндийн лавлагаа.

Эдгээр нь ерөнхий боловсролын хүрээний мэдээлэл бөгөөд сургуулийн өмнөх
боловсролын портфолиод хэрэглэгдэхгүй. Хэрэггүй талбарыг гэрээнд оруулах нь
хамгаалах ёстой өгөгдлийн хэмжээг шалтгаангүй нэмэгдүүлнэ.

## Хавсралт 2 — Мэдээллийн аюулгүй байдлын үүрэг

Дараах хамгаалалт нь системд **аль хэдийн хэрэгжсэн** бөгөөд шаардлагатай бол

| Үүрэг                                       | Хэрэгжилт                                                                                                                                |

| Токен нууц байх                             | `ESIS_TOKEN` зөвхөн серверийн орчны хувьсагчид. Эх кодод нууц үг байхгүй, лог руу бичигдэхийн өмнө `[REDACTED]` болно (`esis.client.ts`) |
| Хандалт эрхээр хязгаарлагдах                | Бүх хүүхдийн өгөгдөл `authz/` модулиар шалгагдана; эрхгүй хандалт 404 буцаана, бичлэг байгаа эсэхийг илчлэхгүй                           |
| Байгууллага хооронд тусгаарлагдах           | Мөр бүр `kindergartenId` агуулна, repository давхарга бүрд суурь шүүлт үүрдэг                                                            |
| Хэн юу үзсэн/өөрчилсөн нь мөрдөгдөх         | `AuditLog` — зөвхөн нэмэгддэг, засагдах, устгах боломжгүй                                                                                |
| Устгал сэргээгдэх боломжтой                 | Хатуу устгал байхгүй; `deletedAt` тэмдэглэгээ                                                                                            |
| Файл шууд хаягаар нээгдэхгүй                | Хаалттай хадгалалт, эрх шалгасны дараа 5 минутын түр хүчинтэй холбоос                                                                    |
| Нууц үг сэргээгдэхгүй хэлбэрээр хадгалагдах | argon2id                                                                                                                                 |

Нэмж хүлээх үүрэг:

- Авсан мэдээллийг **зөвхөн гэрээнд заасан зорилгоор** ашиглана; гуравдагч
  этгээдэд дамжуулахгүй, зар сурталчилгаа, дүн шинжилгээний бүтээгдэхүүнд
  ашиглахгүй.
- Цэцэрлэгтэй байгуулсан гэрээ дуусгавар болмогц тухайн байгууллагын хүрээнд
  татсан мэдээллийг устгаж, актаар баталгаажуулна.
- Мэдээллийн аюулгүй байдлын зөрчил илэрвэл **24 цагийн дотор** БМТТ-д
  мэдэгдэнэ. (Санал болгож буй хугацаа. Журамд өөр хугацаа заасан бол түүнийг
  дагана — журмын эх бичвэрийг §0-д дурдсанчлан хараахан уншаагүй.)
- Синхрончлол нь тогтмол давтамжтай, дараалалд (BullMQ) ажиллах бөгөөд
  ESIS-ийн үйлчилгээнд ачаалал үүсгэхгүй. Санал болгож буй давтамж: өдөрт нэг
  удаа, ажлын бус цагт.

1. Жинхэнэ хариултын жишээг энэ файлын доор `## Хариултын жишээ` гэсэн хэсэгт
   хадгална.
2. `apps/api/src/integrations/esis/esis.schemas.ts` — Zod схем. ESIS-ийн
   талбарын нэрийг энэ хавтаснаас гадуур хэн ч мэдэхгүй байх ёстой.

   лавлах ID, анхны утга) — `нэмэлт.md` §15-ын дагуу, багана биш хүснэгт.
5. Синхрончлол BullMQ дээр, хүсэлтийн дотор хэзээ ч биш (CLAUDE.md §6).
