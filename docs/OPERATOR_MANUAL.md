# OPERATOR_MANUAL.md — Операторын гарын авлага

**Хэнд:** платформыг ажиллуулж буй хүнд (superadmin) — цэцэрлэг бүртгэх,
хэрэглэгч үүсгэх, шинэ цэцэрлэгийг ажиллагаанд оруулах.

**Хэнд биш:** багш, эцэг эхийн хэрэглээний заавар биш. Тэдний дэлгэц өөрөө
өөрийгөө тайлбарлах ёстой; энд зөвхөн **чи өөрөө гараар хийх** ажлууд байна.

Бичсэн: 2026-09-19. Кодоос шалгаж бичсэн — товчны нэр, скриптийн нэр, env
хувьсагч бүрийг эх файлаас нь уншсан. Дэлгэц өөрчлөгдвөл энэ файл хуучирна:
өөрчилсөн хүн нь энд мөрийг нь засна.

## Товч зураглал — юу юуны дараа болох вэ

```
1. Платформын оператор (superadmin)        — терминалаас, нэг удаа
2. Цэцэрлэг бүртгэх                        — /platform эсвэл /platform/applications
     └─ эрхлэгчийн бүртгэл + урилга автоматаар үүснэ
3. Эрхлэгч урилгаа аваад нууц үгээ тавина  — /invitation/<token>
4. Эрхлэгч өөрийн цэцэрлэгийг тохируулна:
     Хичээлийн жил → Улирал → Бүлэг → Багш → Хүүхэд → Эцэг эх
5. Тариф, хураамж (санхүү ашиглах бол)     — /finance → «Тариф»
```

★ **Хамгийн чухал зарчим:** энэ системд **хэн ч өөр хүний нууц үгийг
тавьдаггүй**. Хэрэглэгч үүсгэх гэдэг нь _урилга үүсгэх_ гэсэн үг — тухайн хүн
өөрөө `/invitation/<token>` дээр орж нууц үгээ сонгоно. Урилга **7 хоног**
хүчинтэй, **нэг л удаа** ажиллана.

## 1. Платформын оператор (superadmin)

### 1.1 Хамгийн анхны нэвтрэлт — шинэ өгөгдлийн сан дээр

`seed` нь систем даяарх лавлах мөрүүдийг (хөгжлийн чиглэл, үнэлгээний түвшин,
ажиглалтын төрөл) үүсгэдэг бөгөөд хүсвэл нэг superadmin үүсгэнэ:

```bash
SEED_ADMIN_USERNAME=superadmin SEED_ADMIN_PASSWORD='<12+ тэмдэгт>' \
  pnpm --filter @kinder/api seed
```

`SEED_ADMIN_PASSWORD` өгөхгүй бол superadmin **үүсэхгүй** (алгасна) — энэ нь
санаатай: `admin/admin123` төрлийн анхдагч нууц үг бол production дахь арын хаалга.

★ `seed`-ийг **заавал** ажиллуулна: лавлах мөргүйгээр үнэлгээ, ажиглалт хоёр
ажиллахгүй. Харин superadmin-ыг эндээс биш, **§1.2-оор** үүсгэ — нууц үгийг
терминалд бичихгүй байх нь дээр.

### 1.2 Нэртэй оператор бүртгэх — үүнийг илүүд үз

Хуваалцсан нэг `superadmin` бүртгэл нь `AuditLog`-ийг утгагүй болгоно: бүх мөр
нэг хүнийг заана. Тиймээс **хүн бүрт нэг бүртгэл**:

```bash
USERNAME=bat LAST_NAME=Дорж FIRST_NAME=Бат EMAIL=bat@example.mn \
  pnpm --filter @kinder/api exec tsx prisma/add-superadmin.ts
```

- `USERNAME` л заавал. Овог, нэр, и-мэйлийг тухайн хүн урилга хүлээж авахдаа
  өөрөө бөглөж болно.
- Нууц үг **хаана ч үүсэхгүй**. Скрипт ажиллаж дуусаад
  `invite-<username>.txt` файл үүснэ (`chmod 600`) — дотор нь урилгын холбоос.
  **Терминал руу хэвлэгдэхгүй** (scrollback, дэлгэцийн бичлэгт үлдэхээс сэргийлсэн).
- Ашигласны дараа: `rm invite-<username>.txt`.
- Ижил `username`/`email` байвал скрипт **юу ч өөрчлөхгүй** зогсоно — амьд
  системд хэн нэгний нууц үгийг чимээгүй хүчингүй болгохгүйн тулд.

### 1.3 Superadmin юу чадахгүй вэ

Superadmin-д `Membership` **байхгүй**. Тэр хүүхдийн мэдээлэл, хавтас,
ажиглалт, асран хамгаалагчийг **харахгүй** — хандвал `404` авна. Энэ бол
алдаа биш, зориулалт нь (CLAUDE.md §1.1, §1.7). Superadmin-ы хийж болох зүйл:

| Хаана                    | Юу                                                       |
| ------------------------ | -------------------------------------------------------- |
| `/platform`              | Цэцэрлэгүүд, нийт тоон үзүүлэлт, цэцэрлэг бүртгэх        |
| `/platform/applications` | Ирсэн хүсэлтийг батлах/татгалзах, гэрээ үүсгэх           |
| `/platform/[id]`         | Тухайн цэцэрлэгийн ESIS mapping                          |
| `/platform/[id]/esis`    | ESIS холболтын төлөв, эрхийн матриц, endpoint шалгах     |
| `/platform/revenue`      | Санхүү — улсын санхүүжилт, хандалтын төлбөр, хуваарилалт |

## 2. Цэцэрлэг бүртгэх — хоёр зам

### 2.1 Шууд бүртгэх (`/platform` → **«Цэцэрлэг бүртгэх»**)

Чи өөрөө цэцэрлэгийг мэддэг, гэрээ нь өөр сувгаар яригдсан үед хэрэглэнэ.

Цонх нээгдэхэд **бүртгэх арга** сонгоно. **«ESIS-ээс бүртгэх» анхдагчаар
сонгогдсон** байна; «Гар аргаар бүртгэх» нь зөвхөн ESIS-ээс татах боломжгүй
үеийн арга.

**A. ESIS-ээс бүртгэх — гурван алхам**

1. **ESIS мэдээлэл.** «ESIS байгууллагын ID» бичээд **«ESIS-ээс татах»**.
   Нэр, албан ёсны нэр, хаяг, ангилал, өмчийн хэлбэр, ажилтны тоо
   **«Татагдсан мэдээлэл»** карт дээр гарна — эдгээрийг гараар бичихгүй.
   - «Энэ институц аль хэдийн бүртгэлтэй» гэвэл цааш явахгүй.
   - «Цэцэрлэг биш» бол зөвхөн **сануулга**, хориг биш.
   - ESIS хариу өгөхгүй бол зүүн талаас **«Гар аргаар бүртгэх»** руу шилжинэ.
2. **Захирал/Эрхлэгч.** ESIS-ийн ажилтны жагсаалтаас сонгоно — овог, нэр
   автоматаар бөглөгдөнө. **Нэвтрэх нэрийг ESIS өгдөггүй** тул та бичнэ
   (латин үсэг, тоо, `. _ -`). Цэцэрлэгийн утас, и-мэйлийг мөн энд бичнэ —
   **ESIS эдгээрийг буцаадаггүй**.
3. **Мэдээллийг шалгах.** Бүх утгыг нэг хуудсанд харуулна.
   **«Цэцэрлэг бүртгэх»** дарах хүртэл юу ч илгээгдэхгүй.

**B. Гар аргаар бүртгэх** — хоёр хэсэг: «Цэцэрлэгийн мэдээлэл» (нэр заавал,
хаяг, утас, и-мэйл) ба «Эхний удирдлага» (овог, нэр, нэвтрэх нэр заавал).
Ингэж үүссэн цэцэрлэг **ESIS-д холбогдоогүй** үүснэ; дараа нь
`/platform/[id]`-ээс холбоно.

★ ESIS-ээс татсны дараа «Гар аргаар»-руу шилжвэл татсан мэдээлэл **бүхэлдээ
цэвэрлэгдэнэ** — өөрөөр бол «гараар бүртгэсэн» гэж бодож байгаа цэцэрлэг
чимээгүйхэн ESIS-д холбогдчихно.

Аль ч замаар **«Цэцэрлэг бүртгэх»** дарвал цэцэрлэг + эрхлэгчийн бүртгэл +
урилга гурав зэрэг үүснэ. Дэлгэц дээр гарч ирэх **урилгын холбоос/QR-ыг
эрхлэгчид гардуулна** — энэ цонхыг хаасны дараа дахин харуулахгүй.

### 2.2 Цэцэрлэг өөрөө хүсэлт илгээх (`/register` → `/platform/applications`)

Цэцэрлэг нийтийн хуудасны хөл дэх **«Байгууллагын бүртгэл»**-ээр орж маягт
бөглөнө: цэцэрлэгийн нэр, регистрийн дугаар, хүүхдийн тоо, хаяг, эрхлэгчийн
нэр, утас, и-мэйл, тэмдэглэл.

★ Энэ маягт нь **`Kindergarten` үүсгэхгүй** — зөвхөн `KindergartenApplication`
мөр үүсгэнэ. Цэцэрлэг зөвхөн чиний баталсны дараа үүснэ.

Чи `/platform/applications` дээр **«Хүлээгдэж буй»** таб дээрээс хүсэлтийг
нээж **«Батлах»** дарна. Батлахдаа:

| Талбар               | Тайлбар                                             |
| -------------------- | --------------------------------------------------- |
| Админы нэвтрэх нэр   | Эрхлэгч энэ нэрээр нэвтэрнэ                         |
| Суурь хураамж (жилд) | Гэрээн дээр хэвлэгдэнэ, дараа нь **өөрчлөгдөхгүй**  |
| Хүүхэд/сар           | Мөн адил                                            |
| Эхлэх / Дуусах огноо | Гэрээний хугацаа                                    |
| Тэмдэглэл            | **Татгалзахад заавал** — шалтгааныг цэцэрлэгт хэлнэ |

Батлангуут **цэцэрлэг, эрхлэгчийн бүртгэл, гэрээ** гурав зэрэг үүснэ. Гэрээний
PDF дараалалд орох тул хэдэн секундын дараа **«PDF татах»** товч гарч ирнэ.
Урилгын холбоос мөн тэндээ гарна — гардуулаад цонхоо хаа.

### 2.3 Идэвхжүүлэх · Идэвхгүй болгох · Устгах

`/platform`-ийн мөр бүр дээр, мөн `/platform/[id]` дээр гурван үйлдэл байна.

| Үйлдэл              | Юу болох                                                                   | Буцаах уу         |
| ------------------- | -------------------------------------------------------------------------- | ----------------- |
| **Идэвхгүй болгох** | Хэн ч нэвтэрч чадахгүй. Өгөгдөл бүрэн хэвээр                               | Тийм, нэг товшилт |
| **Идэвхжүүлэх**     | Буцаана                                                                    | Тийм              |
| **Устгах**          | Цэцэрлэг жагсаалтаас алга, **бүх гишүүнчлэл хаагдана**, ESIS холболт сална | **Үгүй**          |

★ **Устгах нь soft delete.** Хүүхдийн бүртгэл, хавтас, нэхэмжлэх, `AuditLog`
бүгд **байрандаа үлдэнэ** (CLAUDE.md §3.2) — устдаг зүйл байхгүй. Хаагддаг нь
**`Membership`**: эрх бүр хүсэлт тутамд `Membership`-ээс уншигддаг тул (§1.3)
зөвхөн цэцэрлэгийн мөрийг тэмдэглэвэл захирал нь юу ч болоогүй юм шиг үргэлжлүүлэн
ажиллана.

★★ **Баталгаажуулахдаа цэцэрлэгийн нэрийг бичнэ.** `window.confirm`-ыг хүн
рефлексээр хаадаг; нэр бичих нь тэгж болдоггүй хамгийн хямд хамгаалалт.

★★★ **ESIS institution ID суларна.** Тэр багана `@unique` бөгөөд `deletedAt`-ыг
мэддэггүй тул устгасан цэцэрлэг дээр үлдвэл тэр институцийг **дахин хэзээ ч**
бүртгэж болохгүй болно. Устгахад `esisInstitutionId`, ажилтны кэш, бүртгэлийн
код гурав цэвэрлэгдэнэ.

Устгасан үйлдэл `AuditLog`-т `DELETE` мөрөөр, өмнөх нэр, идэвхтэй эсэх,
institution ID-тайгаа бичигдэнэ — `/admin/audit` эсвэл §8.2-ын SQL-ээр уншина.

## 3. Урилга гардуулах

Урилга үүсэх бүрд **нэг л удаа** харагдах цонх гарна: холбоос, хуулах товч,
QR код. QR нь зөвхөн тэр холбоосыг агуулна — дэлгэцнээс утас руу URL зөөх арга,
өөр credential биш.

Урилгыг хүлээж авсан хүн `/invitation/<token>` дээр:

| Хэн     | Юу бөглөх                                              |
| ------- | ------------------------------------------------------ |
| Ажилтан | Овог, Нэр, **И-мэйл** (үүгээрээ нэвтэрнэ), нууц үг     |
| Эцэг эх | Нэр, утас, хүүхдийн юу нь болох, нууц үг (**овоггүй**) |

Нэвтрэхдээ **нэвтрэх нэр, утас, эсвэл и-мэйл** — гурвын аль нэгийг нь болно.

**Урилга хугацаа нь дуусвал** дахин урь. Хуучин холбоос сэргэхгүй.

## 4. Хэрэглэгч үүсгэх — дөрвөн зам, алийг нь хэзээ

Ихэнх тохиолдолд **чи биш, цэцэрлэгийн эрхлэгч** үүсгэнэ. Оператор нь
эрхлэгчээс доош ордоггүй — цэцэрлэг бүртгэснээр чиний ажил дуусдаг.

### 4.1 `/admin/users` → **«Хэрэглэгч нэмэх»** — ердийн зам (эрхлэгч хийнэ)

Овог, Нэр, Нэвтрэх нэр, и-мэйл (заавал биш), **Эрх**: Захирал/Эрхлэгч, Багш,
Эцэг эх, Тогооч, Нягтлан. Нууц үг асуухгүй — урилга үүснэ.

★ **Эцэг эхийг эндээс бүү үүсгэ** (дэлгэц өөрөө сануулна): хүүхэдгүй бүртгэл
үүснэ. Эцэг эхийг §4.3-аар ур.

### 4.2 `/admin/staff-code` — ажилтан өөрөө бүртгүүлэх (ESIS-тэй үед)

Гурван карт:

1. **«Код гаргах»** — нэг удаа харагдах код. Эрхлэгч үүнийг ажилтнууддаа өгнө.
   Дахин харуулах боломжгүй; мартвал шинийг гаргана. Хуудсыг дахин ачаалахад
   хоосон харагдана — код алдагдсан гэсэн үг биш, энэ дэлгэц зөвхөн энэ
   session-д гаргасан кодыг л мэднэ.
2. **«Жагсаалтыг шинэчлэх»** — ESIS дээрх ажилтны жагсаалтыг дахин татна.
   Шинэ багш ESIS дээр нэмэгдсэн бол **эхлээд үүнийг дар**, эс тэгвээс тэр
   хүн өөрөө бүртгүүлж чадахгүй.
3. **Бүртгүүлсэн ажилтнууд** — хэн кодоор орсныг хянана. Батлах алхам байхгүй
   (захиалагчийн шийдвэр), харин **«Эрхийг хураах»** байна.

Ажилтан `/staff-register` дээр **код + өөрийн регистрийн дугаар** оруулаад
шууд `/invitation/<token>` руу шилжиж нууц үгээ тавина.

★ Буруу код, жагсаалтад байхгүй регистр, хуучирсан жагсаалт — **бүгд яг ижил
алдааны мессеж** өгнө. Энэ санаатай: ялгаатай хариу өгвөл маягт нь «энэ
регистрийн дугаар энд ажилладаг уу?» гэдгийг хэн ч шалгах хэрэгсэл болно.

### 4.3 Эцэг эх урих — хүүхдийн хуудаснаас

`/children/[childId]/general` → **«Асран хамгаалагч»** хэсэг → **«Урих»**.

Багш юу ч бөглөхгүй — нэг товч. Хүүхэдтэй холбоо нь тэр агшинд үүсэх тул
урилга яг **нэг хүүхдийн** хавтсыг нээнэ. Эцэг эх өөрийн нэр, утас,
хамаарлаа өөрөө бөглөнө.

Эрх хураах: тухайн асран хамгаалагчийн мөрөн дэх **«Харах эрхийг хураах»**.

### 4.4 Терминалаас — зөвхөн өөр арга үлдэхгүй үед

```bash
# Ажилтны бүртгэл, нууц үгтэй нь (нээлттэй текстээр!)
USERNAME=togooch ROLE=COOK LAST_NAME=Дорж FIRST_NAME=Сараа \
KINDERGARTEN_ID=<uuid> PASSWORD='<12+ тэмдэгт>' \
  pnpm --filter @kinder/api exec tsx prisma/add-staff-account.ts
```

- `ROLE`: `ADMIN | TEACHER | PARENT | COOK | ACCOUNTANT`.
  ★ **`PARENT`-ийг эндээс бүү үүсгэ.** Скрипт зөвшөөрдөг ч `Guardianship`
  үүсэхгүй тул хүүхэдгүй эцэг эх гарна — §4.3-аар ур. Дэлгэц дээр анхааруулга
  байдаг, энд байхгүй.
- Бүртгэл нь байвал **хөндөхгүй** зогсоно (хэн нэгний нууц үгийг дарахгүй).
- И-мэйлийг `<username>@nomadkids.mn` гэж өөрөө тавина.
- ★ Энэ нь **сүүлчийн арга**. Нууц үгийг чи мэдэж байгаа гэдэг нь §3-ын бүх
  логикийг сэлгэнэ; боломжтой бол §4.1-ийн урилгыг ашигла.

```bash
# Нууц үг сэргээх — SMTP тохируулагдаагүй үед эрхлэгчийг оруулах цорын ганц зам
DATABASE_URL=… pnpm --filter @kinder/api reset-password <username> <password>
```

Энэ нь **зориудаар endpoint биш**. HTTP-ээр хүрэх, хэн болохыг батлахгүйгээр
нууц үг тавьдаг юм бүхэн бол арын хаалга. Үүнд shell болон `DATABASE_URL`
хэрэгтэй.

> ⚠ `POST /users/:id/password-reset` (1 цаг хүчинтэй) API дээр байсаар байгаа
> ч **дуудах дэлгэц одоо байхгүй** — 2026-09-08-нд хэрэглэгчийн жагсаалт
> ESIS-ийн панелиар солигдоход мөрийн товчнууд нь хамт алга болсон. Тиймээс
> нууц үг сэргээх бодит хоёр зам: `/forgot-password` (SMTP тохируулагдсан бол)
> ба дээрх скрипт.

## 6. Тохиргоо — үүнийг хийхгүй бол хэсэг нь хоосон ажиллана

### 6.1 Систем даяарх лавлах (бүх цэцэрлэгт нийтлэг)

Хөгжлийн чиглэл, үнэлгээний түвшин, ажиглалтын төрөл нь `kindergartenId = NULL`
буюу **систем даяарх** мөрүүд. Эдгээрийг `seed` тавина. Жагсаалт өөрчлөгдвөл
амьд өгөгдлийн санд хүргэх:

```bash
pnpm --filter api exec tsx scripts/apply-system-config.ts
```

Энэ нь `code`-оор тааруулж нэр, эрэмбийг шинэчилж, жагсаалтад байхгүй болсон
системийн мөрийг soft-delete хийнэ. Өөр юу ч хөндөхгүй. Цэцэрлэг өөрийн
нэмэлт чиглэл нэмэх бол `/admin/assessment-config`.

### 6.2 Санхүүгийн тариф — **хоосон ирдэг, зориудаар**

`FundingRule` хүснэгт **хоосон** ачаалагддаг: нэг ч тариф код дотор бичигдээгүй
(`нэмэлт.md` §4-ийн шаардлага). Оруулах хүртэл санхүүгийн тооцоолол
ажиллахгүй — `/finance` дээр «Энэ сард хүчинтэй тариф алга» гэж гарна.

`/finance` → **«Тариф»** хэсгээс дүрмээ үүсгэнэ. Дараа нь `/admin/funding`
(«Ирц ба тооцоолол») сарын бүртгэлийг тооцож, Excel-ээр гаргана.

### 6.3 Хандалтын төлбөр (QPay)

`ACCESS_FEE_AMOUNT` — нэг хүүхэд × нэг хичээлийн жил, төгрөгөөр.

- `0` = **хаалт унтраалттай**, энэ нь анхдагч. Тохируулаагүй систем эцэг эхийг
  хүүхдийнх нь мэдээллээс хаахгүй.
- QPay зөвхөн **үүнд** хэрэглэгдэнэ. Сургалтын төлбөр, хоолны нэхэмжлэх нь
  бэлэн мөнгө/шилжүүлгээр, нягтлан бүртгэнэ.
- Төлөөгүй эцэг эх **402** авна (404 биш) — энэ бол системийн цорын ганц
  тийм газар. Эрхийн шалгалт эхэлж ажилладаг тул танихгүй хүн ямар ч үед 404
  л авна.

### 6.4 ESIS

Токен, base URL нь **байршуулалтын тохиргоо** (`ESIS_TOKEN`, `ESIS_BASE_URL`),
институц нь **цэцэрлэг тус бүрийн** тохиргоо (`Kindergarten.esisInstitutionId`,
`/platform/[id]`-ээс тавина).

- ESIS-ийг бүхэлд нь хоосон орхиж болно — бусад бүх зүйл хэвийн ажиллана.
- **Хагас тохируулбал** production дээр boot дээрээ зогсоно. Энэ санаатай:
  тохируулагдсан юм шиг харагдаад яамны authentication алдаа болж унахаас
  илүү шударга.
- **Demo mode байхгүй** (2026-09-14-нд устгагдсан). ESIS панель хоосон байвал
  ямар нэг fallback мөр зурж болохгүй — холболт эсвэл эрх дутуу гэсэн үг.
- Дэлгэрэнгүйг `docs/ESIS_TRIAL_STATE.md` — тодорхойлолт биш, **амьд
  үйлчилгээ юу хийдгийг** бичсэн файл.

★★ **Хичээлийн жил, улирал нэмэх нь ESIS рүү юу ч илгээхгүй.** Хоёулаа
дотоод бүртгэл — `createSchoolYear` (`tenants.service.ts`) ба `createTerm`
(`assessment.service.ts`) нь ESIS-ийн ямар ч замд хүрдэггүй. `/admin/school-years`
дээрх ESIS панель нь **зөвхөн уншина** (`academicYearStatuses` — яамны нээсэн,
хаасан огноотой тулгах). `/admin/terms` дээр панель ч байхгүй.

Энэ бүтээгдэхүүнээс ЯАМ руу явдаг **бичилт бол ердөө дөрөв**, бүгд бүлгийн
тухай: `groupCreate`, `groupUpdate`, `groupDelete`, `groupInstructor`. Бүгд
дараалалд орж, **захирал батласны дараа** илгээгддэг (`EsisWriteRequest`).
Тэдгээрийн payload доторх `academicYear` нь ч бидний `SchoolYear` хүснэгтээс
биш, **ESIS-ийн өөрийнх нь бүлгийн мөрөөс** уншигдана — тиймээс хичээлийн жил
нэмэх нь дам замаар ч гэсэн юу ч илгээхгүй.

   ```bash
   pnpm --filter @kinder/api prisma:deploy
   ```

2. **Шөнийн нөөцлөлт** — `15 2 * * * /opt/nomadkids/scripts/backup.sh`, root-ын

3. **Шинэ env тохиргоо бүр `.env.example`-д мөртэй болно** (CLAUDE.md §1.5).

   `up -d --build` нь `env_file`-ыг **дахин уншихгүй** — хувьсагч өөрчилсөн бол

### 8.1 Бүтээгдэхүүн дотроос — тоон үзүүлэлт

| Хаана                | Юу харагдах                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `/platform`          | Нийт цэцэрлэг, бүлэг, хүүхэд, багш/ажилтан, **идэвхтэй эцэг эх** — 5 тоо                   |
| `/admin`             | Нэг цэцэрлэгийн: суралцагч, өнөөдрийн ирц, бүлэг, ажилтан, эцэг эх, баримт, тайлангийн тоо |
| `/platform/revenue`  | Улсаас цэцэрлэгүүдэд өгсөн санхүүжилт, хандалтын төлбөр, цэцэрлэг тус бүрээр               |
| `/finance/dashboard` | Нэг цэцэрлэгийн 9 санхүүгийн үзүүлэлт — бүгд уншихад тооцогддог                            |

тайланд оруулах бол **огноог нь бичиж** screenshot ав — маргааш өөр тоо гарна.

### 8.2 «Ингэж ажилласан» гэдгийн бодит нотолгоо — `AuditLog`

Тайланд хамгийн их хэрэг болох нь энэ. Хүснэгт бүр мөрөнд: `action`,
`objectType`, `actorUserId`, `actorRole`, `actorLabel`, `childId`, `ipAddress`,
`createdAt`. Нэмэх зөвхөн боломжтой — засах, устгах боломжгүй (CLAUDE.md §3.2).

`/admin/audit` дэлгэц нь шүүж харуулна, гэхдээ **Excel гаргалт байхгүй**.
Хураангуй тоо хэрэгтэй бол VPS дээр шууд:

```bash
docker compose -f docker-compose.prod.yml exec -T db \
  sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
select date_trunc('day', "createdAt") as day, action, count(*)
from audit_logs
where "createdAt" >= now() - interval '30 days'
group by 1, 2
order by 1 desc, 3 desc;
SQL
```

Идэвхтэй хэрэглэгч (сарын давхцалгүй тоо) — ижил бүрхүүлээр:

```sql
select count(distinct "actorUserId")
from audit_logs
where "createdAt" >= now() - interval '30 days';
```

★ **Гурван зүйл яг ийм байх ёстой**, эс бөгөөс ажиллахгүй:
`$POSTGRES_USER`, `$POSTGRES_DB` нь **db контейнерийн доторх** хувьсагчид тул
`sh -c '…'` дотор, **ганц хашилтанд** байх ёстой — host дээр задарвал хоосон
утга орно. SQL нь `-c "…"`-аар биш **stdin-ээр** (heredoc) ордог тул `"` болон
`'` тэмдгийг escape хийх шаардлагагүй. Heredoc уншигдахын тулд `-T` (TTY
хуваарилахгүй) заавал.

Нэвтрэлт нь `sessions` ба `login_attempts` хүснэгтэд тусдаа байна.

### 8.3 Вэб серверийн лог — Caddy

Гурван домэйн тус бүр өөрийн access log-той, JSON мөрөөр:

```
/data/access-web.log     nomadkids.mn
/data/access-api.log     api.nomadkids.mn
/data/access-media.log   media.nomadkids.mn
```

`caddy_data` volume дотор, 10 MB тутам эргэлдэж **сүүлийн 5-ыг** хадгална —
ачаалал ихтэй үед энэ нь хэдхэн өдөр. Урт хугацааны тайлан хэрэгтэй бол
**өнөөдөр** хуулж эхэл:

```bash
docker compose -f docker-compose.prod.yml exec caddy cat /data/access-web.log > web.log
jq -r '.request.uri' web.log | sort | uniq -c | sort -rn | head -20
```

★ Access log-д **хүүхдийн id URL дотор** байдаг (`/children/<uuid>/…`). Тайланд
оруулахдаа зам нь бүхэлдээ биш, ерөнхийлсөн хэлбэрээр (`/children/:id`) оруул.

### 8.4 Тайланд юу оруулах нь зөв вэ

1. `/platform`-ийн 5 тоо — огноотой (хэдэн цэцэрлэг, хэдэн хүүхэд, хэдэн эцэг эх).
2. `AuditLog`-оос сарын үйлдлийн тоо, төрлөөр — «системд бодитоор ажилласан» гэдгийн нотолгоо.
3. `/platform/revenue`-ийн санхүүгийн дүн.
4. ESIS: `docs/ESIS_API_READINESS.md` §1.1.9-д амьд хүсэлт, хариу бүр бичигдсэн байгаа.
