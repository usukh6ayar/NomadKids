# Дизайн шинэчлэлийн тайлан ба ESIS-ийн бэлэн байдал

**Огноо:** 2026-09-03 · **Салбар:** `redesign/ui-2026-09` · **PR:** #30

Энэ баримт хоёр асуултад хариулна:

1. Юу хийсний үндсэн дээр шаардлагууд хангагдсан гэж хэлж байгаа вэ?
2. ESIS-ийн API-уудыг хүлээж авахад бэлэн үү?

Хоёр дахь асуултын хариу **"хэсэгчлэн"** — доор яг юу бэлэн, юу бэлэн биш болохыг
ялгаж бичсэн.

---

## 1. Шаардлага хангасан гэдгийг юугаар нотолж байна

Дизайны ажлын хамгийн том эрсдэл нь "сайхан харагдаж байна" гэдэг субъектив
дүгнэлт. Тиймээс шалгаж болох зүйлсийг л шаардлага хангасан гэж үзсэн: тест,
хөрвүүлэлт, эсвэл браузер дээрх бодит хэмжилт. Доорх бүх тоо давтан гаргаж
болно.

### 1.1 Автомат шалгуурууд

| Шалгуур                                     | Үр дүн                              |
| ------------------------------------------- | ----------------------------------- |
| Web тест (`pnpm --filter web test`)         | 38 файл · **499 тест**              |
| API тест (`pnpm --filter @kinder/api test`) | 63 файл · **1672 тест** (1 skipped) |
| Web typecheck                               | цэвэр                               |
| API typecheck                               | цэвэр                               |
| ESLint (`apps/web`, `apps/api/src`)         | цэвэр                               |
| Production build (`next build`)             | амжилттай                           |

★ **Build-ыг тусад нь ажиллуулсан нь санамсаргүй биш.** Vitest нь Tailwind-ыг
хөрвүүлдэггүй, тиймээс `@utility` буруу бичигдсэн байсан ч 499 тест ногоон
өгөөд build дээр унана. Шинэ CSS гарсан bundle дотор байгааг мөн шалгасан
(`.next/static/chunks/*.css` дотор `--shadow-md`, `--color-sunken`,
`page-band`, `card-interactive`, `fieldset{min-width:0}`).

### 1.2 Хатуу хязгаарлалтууд эвдрээгүй нь

Кодын сан өөрөө шаардлагаа тестээр бэхэлсэн байдаг. Эдгээр нь одоо ч ногоон:

- `tokens.test.tsx` — `app/`, `components/` дотор дурын фонтын хэмжээ, радиус
  бичихийг хориглоно. Тиймээс бүх шинэ утга `globals.css`-ийн `@theme`-ээр
  дамжсан.
- `responsive.test.tsx` — товч ≥44px, input/select 48px, textarea ≥112px,
  палитрын hex утгууд, `:focus-visible` outline.
- `sidebar.test.tsx`, `landmarks.test.tsx`, `page-header.test.tsx`,
  `vocabulary.test.tsx` — навигаци, landmark нэр, монгол мөрүүд.

★ **Гол механик:** эдгээр тест нь **токены нэрийг** барьдаг, утгыг нь биш.
`ui-foundation` нь `Card`-ын класс мөрөнд `shadow-sm` байхыг шаарддаг;
`page-header` нь h1-д `text-display` байхыг шаарддаг. Тиймээс `@theme` дотор
тэдгээр нэрсийн **утгыг** өөрчилснөөр бүтээгдэхүүн бүхэлдээ өнгө төрхөө
сольсон боловч нэг ч assertion эвдэрсэнгүй. Энэ бол `globals.css` өөрөө
бичсэн үндэслэл: _"нэг файл засахад 27 дэлгэц өөрчлөгдөнө"_.

### 1.3 Браузер дээрх бодит хэмжилт

Puppeteer-ээр бодит Chrome дээр аппыг ажиллуулж, 5 эрхээр (багш, захирал, эцэг
эх, тогооч, нягтлан) 375 / 390 / 1440 өргөнд **270 route×width** шалгалт хийсэн.
Зөвхөн зураг авсангүй — зураг хэлж чадахгүй зүйлсийг хуудсан дотор хэмжсэн:

- хэвтээ overflow (`scrollWidth > clientWidth`),
- 44px-ээс бага tap target,
- ellipsis-ээр тасарсан навигацийн шошго,
- доод цэсний ард нуугдсан агуулга.

**Эцсийн үр дүн: `overflow-x` бүх 270 шалгалтад тэг. Навигацийн шошго
тасрахгүй.**

★★ **Автомат дүгнэлтэд шууд итгээгүй.** Эхний ажиллуулалт 63 "алдаа" өгсөн.
Тэдгээрийн нэлээд хэсэг нь миний шалгуурын алдаа байсан:

| Худал дохио                | Яагаад                                                                                                                                   |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `content-under-bottom-bar` | `main`-ий **padding**-ыг хэмжсэн. `pb-24` (96px) > bar (80px) — зөв ажиллаж байсан. Үлдсэн нь хаалттай `<details>`-ийн нуугдсан агуулга. |
| `truncated-label` (59)     | Бүгд **хүний нэр**. Brief нь навигаци/формын шошгыг хориглодог, нэрийг биш; 244px sidebar-ын ухамсартай буулт гэж кодод тэмдэглэсэн.     |
| `tap-target` 1px           | Radix Select-ийн нуугдсан native control.                                                                                                |

Шалгуурыг гурван удаа зассан. Энэ ялгааг хийхгүйгээр "63 алдаа заслаа" гэж
хэлэх нь худал тайлан болно.

## 2. Юу хийсэн — ангилалаар

### 2.1 Баримтжуулагдсан боловч байхгүй байсан хоёр баталгаа

Эдгээр нь гоо сайхны биш, **алдаа** байсан.

**Ажиглалтын ноорог.** Brief §4.4 нь бичсэн ажиглалтаа алдахыг _"энэ дэлгэцийн
хамгийн муу бүтэлгүйтэл"_ гэж нэрлэдэг, constraint 13 давтдаг. Бодит байдалд
бүх талбар зөвхөн `useState`-д байсан — Back товч, reload, эсвэл утас таб-аа
устгахад бичсэн бүх зүйл алга болдог байв. Brief нь _"энэ баталгааг хадгал"_
гэсэн; хадгалах баталгаа байгаагүй.

Засварлах явцад гурван нэмэлт алдаа илэрч, тус бүрд тест бичсэн:

1. Багшийн форм **эцэг эхийн** ноорогийн түлхүүрийг уншиж байсан. Эрх нь
   `/auth/me`-ээр ирдэг тул эхний render-т `hasRole` хүн бүрд `false` хариулна,
   харин сэргээлт нь `useState` initialiser дотор — нэг удаа, яг тэр render-т.
2. Эхний хадгалалтын дараа autosave **бүрмөсөн үхдэг** байсан ("Дахин бичих"
   ижил формыг дахин ашигладаг).
3. Debounce дотор хадгалбал нислэг дэх бичилт `clear()`-ын **дараа** ажиллаж,
   аль хэдийн хадгалагдсан ажиглалтыг ноорог болгон сэргээдэг байв.

**Ирцийн "Бусад".** Товчнууд зургаан төлөвийг санал болгож, API нь
2026-09-02-оос хойш `OTHER`-ыг хүлээж авдаг байсан ч задаргаа нь таван утгатай
`ATTENDANCE_STATUS_ORDER`-оос баригдаж байсан. Үр дүнд нь "Бусад" гэж
тэмдэглэсэн хүүхэд зөв хадгалагдаж, `recorded` тоолж, доорх chip-үүд тоолохгүй
— дэлгэц дээр өөртэйгээ нэгээр зөрдөг байв.

### 2.2 Дизайны систем

Токен: фонтын шат (body 14→15px, дээд шатууд ялгарсан), гурван түвшний сүүдэр
(өмнө нь Tailwind-ийн саарал default нэг л түвшин), `--color-sunken` (өмнө нь
хоёрхон гадаргуу байсан тул карт доторх самбар "хайрцаг доторх хайрцаг" болдог
байв), `--space-band`/`--space-stack` хэмнэл.

Примитив: Button дарагдах хариу үйлдэлтэй болсон (өмнө нь зөвхөн
`transition-colors` — hover нь энэ бүтээгдэхүүн голдуу ажилладаг мэдрэгчтэй
дэлгэц дээр **байхгүй** зүйл); Field-ийн контрол цагаан дээр цагаан контур
байхаа больж сууринтай болсон; skeleton дөрвөн хэлбэртэй болсон (өмнө нь
самбар, жагсаалт, бүртгэлд ижил 72px саарал зураас); `RegisterSaveBar` нэг
компонент болсон (өмнө нь гурван хуулбар, аль хэдийн зөрсөн).

Замдаа олдсон хоёр жинхэнэ алдаа:

- `:focus-visible` нь `border-radius: 4px` тавьдаг байсан — энэ нь **элемент
  дээр** үйлчилдэг тул фокус авсан бүх дугуй контрол булангаа алддаг байв.
- Sidebar шошгоо `truncate` хийж "Чөлөөний хүсэлт х…" гэж гаргадаг байв —
  constraint 2 яг үүнийг хориглодог.

### 2.3 Дэлгэцүүд

Бүртгэлийн pill-үүд утга илэрхийлсэн өнгөтэй болсон. Өмнө нь 35 хүүхдийг
үнэлсэн хуудас 35 ижил цэнхэр тэгш өнцөгт байсан тул "хэн дутуу вэ" гэдгийг
шошго бүрийг уншиж л мэдэх боломжтой байв. Ирц нь одоо байгаа
`ATTENDANCE_STATUS_CHART_TONE`-ыг, үнэлгээ нь одоо байгаа байрлалд суурилсан
`levelTone()`-ыг **дахин ашигладаг** — тиймээс гурав ч бай зургаан түвшин ч
бай, ямар ч нэртэй байсан ажиллана (§2.3, constraint 20). Энэ нь мөн хоёуланг
нь аль хэдийн зөв хийсэн байсан хоолны бүртгэлтэй нэг эгнээнд оруулсан.

### 2.4 Браузер QA-гаас олдсон алдаанууд

**`/notifications/new` — chip-үүд хүрэх боломжгүй байсан (хамгийн ноцтой).**
`<fieldset>` нь UA-ийн `min-width: min-content`-той тул **375px viewport дотор
1115px өргөн** болсон. Доторх scroller 1147px, `scrollWidth` 1148 — өөрөөр
хэлбэл `canScroll: false`. "Мэдээний төрөл"-ийн эхнийхээс хойшхи бүх chip
дэлгэцийн гадна, гүйлгэж ч хүрэхгүй байв. `html { overflow-x: hidden }` нь
үүнийг **зассан биш, нуусан**. Засвар: `fieldset { min-width: 0 }` →
1165px → 390px.

**`/notifications` — карт бүр хуудсыг түлхэж байсан.** Badge мөр `shrink-0`
байсан бөгөөд администраторын өөрчилдөг ангиллын нэр ("Сургалт, үйл ажиллагаа")
390px дотор 405px болгож, засах/устгах товчийг дэлгэцийн гадна гаргаж байв.

**44px-ээс доош 20+ tap target** — `grid size-9` (36px) icon товчны системийн
загвар 8 файлд, `min-h-[40px]` segmented control 6 файлд (голдуу **дизайн
шинэчлээгүй** тогооч/админы дэлгэцүүд), эцэг эхийн утасны холбоос 24px,
мэдэгдлийн гарчгийн холбоос 18px.

## 3. Юу хийгээгүй — ил тод

- **Дэлгэц бүрт ижил гүнзгий ажил хийгээгүй.** Композицийн ажил brief-ийн
  нэрлэсэн зургаан дэлгэц (самбар, хүүхдүүд, хүүхдийн хуудас, шинэ ажиглалт,
  явцын үнэлгээ, ирц) дээр, нэмээд хоол, мэдээ, хавтас, улирлын тайлан дээр
  хийгдсэн. Үлдсэн ~20 дэлгэц системийг **өвлөж** авсан — фонт, өндөрлөг,
  input, товч, хоосон төлөв нь бодитоор өөрчлөгдсөн ч тус бүрчлэн дахин
  зохиогдоогүй.

- **`Явцын үнэлгээ`-ний дараалал өөрчлөөгүй.** 1440×900 дээр `Улирал` /
  `Хөгжлийн чиглэл` сонгогч **гүйлгэхгүйгээр харагдахгүй** — өмнө нь
  `GroupCoverage` бүтэн дэлгэц эзэлдэг. Энэ нь brief §4.6-тай зөрчилддөг ч
  кодод **2026-08-31-ний захиалагчийн шийдвэр** гэж тэмдэглэгдсэн: _"эхний
  зүйл нь бүлэг ямар байгаа нь байх ёстой, тохируулах хоёр dropdown биш"_.
  Захиалагчийн бичсэн зааврыг чимээгүй эргүүлэхгүй — шийдэх нь та.

- **Нэг тест нэг удаа унасныг оношлоогүй.** `funding-register.test.tsx` бүтэн
  ажиллуулалтад унаж, дангаараа өнгөрсөн (12/12), дараа нь дөрвөн удаа дараалан
  өнгөрсөн. Бүтэн reporter гаралтыг барьж амжаагүй — CLAUDE.md §4.4 яг үүнээс
  сэрэмжлүүлдэг. Тиймээс §4.4-т **онош биш, өгөгдлийн цэг** гэж бүртгэсэн.

- **Vercel-ийн deploy унаж байгаа.** Энэ нь миний өөрчлөлт биш: app бүрэн
  хөрвүүлэгдэж, TypeScript өнгөрч, хуудсууд үүсээд, дараа нь Vercel-ийн
  өөрийнх нь `onBuildComplete` алхам `next-server.js.nft.json` олдохгүй гэж
  унадаг (Next 16 + Turbopack-ийн file-tracing нийцгүй байдал). Сүүлийн 19
  цагийн **бүх** Vercel deploy ижилхэн унасан, миний салбар үүсэхээс өмнө.
  Production нь Vercel дээр биш (§4).

## 5. ESIS-ийн API-уудыг авахад бэлэн үү?

**Богино хариу: хил хязгаар нь бэлэн, интеграци нь бэлэн биш.**

Энэ нь дутагдал биш, ухамсартай шийдвэр — `esis.service.ts` өөрөө үүнийг
бичсэн байдаг.

### 5.1 Бэлэн байгаа зүйл

`apps/api/src/integrations/esis/` дотор:

| Бүрэлдэхүүн              | Юу хийдэг                                                                                                                                                                                                                                                               |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `esis.config.ts`         | Тохиргоог boot дээр шалгана. Хэсэгчлэн бөглөсөн бол production-д ачаалахаас татгалзана — "тохируулагдсан юм шиг харагдаад яамнаас authentication алдаа болж унах" байдлаас сэргийлнэ. `isConfigured` нь "унтраалттай" гэдгийг **алдаа биш, энгийн төлөв** болгож өгдөг. |
| `esis.client.ts`         | HTTP давхарга: токеныг зөвхөн энд уншина, timeout (`ESIS_TIMEOUT_MS`), алдааны төрөлжүүлэлт, лог. Node-ийн `fetch` — нэмэлт HTTP хамаарал байхгүй.                                                                                                                      |
| `redact()` / `excerpt()` | Алдааны мессеж, хариуны биеийг **хадгалахаас өмнө** цэвэрлэнэ. Зөвхөн path логлоно, бүтэн URL биш (query дотор нууц утга явж болзошгүй), header огт логлохгүй.                                                                                                          |
| `esis.service.ts`        | Аппликейшн рүү харсан цорын ганц үүд.                                                                                                                                                                                                                                   |
| `health.controller.ts`   | ESIS-ийн төлөвийг readiness дээр мэдээлнэ — токен, түүний урт хүртэл харуулахгүй.                                                                                                                                                                                       |
| `esis.client.test.ts`    | **19 тест**.                                                                                                                                                                                                                                                            |

Өөрөөр хэлбэл: **тохиргоо, нэвтрэлт, timeout, алдаа, лог, нууцлал** — эдгээр нь
ESIS-ийн API ямар байхаас үл хамааран мэдэгдэх зүйлс бөгөөд бүгд бичигдсэн,
тесттэй.

### 5.2 Бэлэн БИШ зүйл

`EsisService`-д **домэйн метод байхгүй**. `syncChildren()` алга,
`fetchInstitution()` алга, `pushAttendance()` алга. Файл өөрөө шалтгааныг
бичсэн:

> _"Бид ESIS-ийн API баримт бичгийг хараагүй, тиймээс тэдгээрийн аль нь ч
> зохиомол схем дээрх зохиомол endpoint болно — нэг нь үүссэн даруйд дэлгэц
> түүн дээр баригдаж, таамаг тархана."_

Мөн:

- **Аппликейшны юу ч үүнийг дуудахгүй.** Модулийн графт холбогдсон нь зөвхөн
  тохиргоог boot дээр шалгуулах, тест ажиллуулах зорилготой. `EsisService`-ийг
  ашиглаж буй цорын ганц газар бол `health.controller.ts` — төлөв мэдээлэх.
- **Бодит endpoint дуудагдаж үзээгүй.** Sandbox эсвэл баримт бичиггүй тул
  ямар ч хүсэлт бодит үйлчилгээний эсрэг шалгагдаагүй.
- `request<T>()` нь **ерөнхий escape hatch** — хариуны хэлбэр үнэхээр
  мэдэгдэхгүй байгаа тул `parse` (Zod-ийн `schema.parse`) дамжуулж хилийн
  дээр нарийсгахыг шаарддаг.

### 5.3 Бодитоор холбоход юу хэрэгтэй вэ

1. **ESIS-ийн API баримт бичиг** — endpoint-ууд, authentication схем, хариуны
   бүтэц. Энэ байхгүй бол дараагийн алхам бүр таамаг.
2. **Sandbox / тест орчны эрх** — `ESIS_BASE_URL`, `ESIS_TOKEN`,
   `ESIS_INSTITUTION_ID`.
3. Endpoint бүрд **Zod схем**, `request<T>()`-д `parse` болгон дамжуулах.
4. Домэйн метод бүрийг **тусдаа, хянагдах өөрчлөлт** болгож нэмэх.
5. Аль чиглэлд өгөгдөл урсахыг тодорхойлох (яамнаас татах уу, яам руу илгээх
   үү, хоёулаа юу) — энэ нь authorization болон аудитын шаардлагыг өөрчилнө.

### 5.4 Дүгнэлт

> ESIS-ийн API ирэхэд **дэд бүтцийг дахин бичих шаардлагагүй** — тохиргоо,
> нэвтрэлт, timeout, лог, нууцлал бэлэн. Харин **интеграци өөрөө бүхэлдээ
> хийгдэх ёстой**, тэр нь баримт бичиг ирсний дараа эхэлнэ.

"ESIS бэлэн" гэж хэлэх нь буруу байх болно. "ESIS-ийг хүлээж авах хил бэлэн"
гэдэг нь зөв.
