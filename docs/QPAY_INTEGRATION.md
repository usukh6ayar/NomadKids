# QPAY_INTEGRATION.md — онлайн төлбөрийн холболт

**Хамрах хүрээ:** `нэмэлт.md` §8 "Онлайн төлбөр". Захиалагч 2026-08-31-нд
санхүүгийн модулийг эхлүүлэхээр шийдэж, QPay-ийн мерчант эрх гарт орсон.

**Төлөв:** §7 нэхэмжлэл, §8 QPay-ийн холболт, эцэг эхийн дэлгэц — **бүгд
баригдсан**, 84 тест ногоон. Үлдсэн нь бодит холболтын нэг удаагийн туршилт
(§5, §6).

> ★ **Энд ямар ч нууц үг байхгүй, хэзээ ч байх ёсгүй.** QPay-ээс ирсэн клиент
> нэр, нууц үг нь зөвхөн байршуулалтын орчны хувьсагчид (`QPAY_USERNAME`,
> `QPAY_PASSWORD`) орно — CLAUDE.md §1.5. Доор зөвхөн нууц биш зүйлс бичигдсэн.

## 2. QPay-ийн зааврын гурван шаардлага

Ирсэн бичигт гурван зүйлийг тодорхой хэлсэн бөгөөд гурвуулаа шууд
хэрэгжүүлэлтийн шийдвэр болно:

### 2.1 Токеныг timestamp-аар нэг удаагийн давтамжтай үүсгэх

> "Token-ийн хугацааг timestamp-д тулгуурлан нэг удаагийн давтамжтайгаар
> үүсгэдэг байдлаар хөгжүүлнэ үү"

★ Энэ нь ESIS-ийн загвараас **ялгаатай**. ESIS нь урт хугацааны нэг токентой
(`ESIS_TOKEN` орчны хувьсагч), QPay нь `auth/token`-оос богино хугацааны токен
авдаг ба хугацаа нь дуусахаар дахин авна.

Тиймээс QPay-ийн клиент нь ESIS-ийн клиентийг хуулж болохгүй: токены нөөц
(cache), хугацаа дуусахыг мэдэх, зэрэг хүсэлтүүд нэг л удаа шинэчлэх (single
flight) логик хэрэгтэй. Хэрэв зэрэг арван хүсэлт токен дууссныг зэрэг олж
үзвэл арван удаа `auth/token` дуудвал QPay биднийг хязгаарлаж болно.

### 2.2 Callback-ийг **хүлээж авсны дараа шалгаж баталгаажуулах**

> "Төлбөр амжилттай төлөгдсөн мэдээллийг callback URL-аар хүлээн авсны дараа
> **шалгаж баталгаажуулна уу**"

★★ **Энэ бол хамгийн чухал аюулгүй байдлын мөр.** Callback URL нь нээлттэй
байх ёстой — QPay түүн рүү дууддаг — тиймээс **хэн ч** тэр хаяг руу "төлөгдлөө"
гэсэн хүсэлт илгээж чадна. Callback-ийн агуулгад итгэвэл хүн бүр төлбөргүйгээр
нэхэмжлэлээ хаана гэсэн үг.

Зөв урсгал:

```
QPay → POST /v1/payments/qpay/callback  (payment_id)
  1. Хэрэв энэ payment_id-г аль хэдийн боловсруулсан бол — эрт буцах
     (Payment.idempotencyKey, unique индекс)
  2. QPay-ийн API руу ӨӨРСДӨӨ хандаж төлбөрийг шалгах
  3. Зөвхөн QPay өөрөө баталсан үед Payment мөр үүсгэх
```

Өөрөөр хэлбэл callback нь **мэдэгдэл**, баталгаа биш. `Payment.rawPayload`-д
QPay-ийн хариуг хадгална — маргаан гарвал хэрэгтэй.

### 2.3 Давхардлаас хамгаалах

QPay callback-ийг дахин илгээж болно (сүлжээ тасрах, timeout). `Payment` дээр
`idempotencyKey` талбар unique индекстэйгээр **аль хэдийн байгаа** —
`schema.prisma` дээрх тайлбарыг үзнэ үү. Түлхүүр нь QPay-ийн `payment_id`-аас
үүснэ, тиймээс хоёр дахь дуудлага constraint зөрчил өгч, service түүнийг
"аль хэдийн бүртгэсэн" гэж таньж алгасна.

## 3. Юу бэлэн болсон бэ

§8-ыг барихад шаардлагатай схем **аль хэдийн байна** (`20260831074837`):

| Хэрэгцээ                 | Хаана                                            |
| ------------------------ | ------------------------------------------------ |
| Төлбөрийн мөр            | `Payment`                                        |
| QPay-ийн ID хадгалах     | `Payment.providerInvoiceId`, `providerPaymentId` |
| Давхардлаас хамгаалах    | `Payment.idempotencyKey` + unique индекс         |
| QPay-ийн хариуг хадгалах | `Payment.rawPayload`                             |
| §8-ын төлөвүүд           | `PaymentStatus`, `InvoiceStatus`                 |
| Буцаалт (§14)            | `Payment.reversalOfId` + reversal урсгал, 6 тест |
| Төлбөрийн арга           | `PaymentMethod.QPAY`                             |

`PaymentStatus.PENDING` нь яг QPay-д зориулагдсан: QR үүсгэсэн ч төлөгдөөгүй
төлөв. Гараар бүртгэсэн төлбөр шууд `PAID` болдог — тэнд баталгаажуулах
гуравдагч тал байхгүй.

## 4. Юу баригдсан бэ (2026-08-31)

Сервер ба эцэг эхийн дэлгэц **хоёулаа бэлэн**, 45 тест ногоон
(17 клиент + 18 төлбөр + 10 дэлгэц).

| Файл                                   | Юу хийдэг                                             |
| -------------------------------------- | ----------------------------------------------------- |
| `integrations/qpay/qpay.config.ts`     | Итгэмжлэл, `describe()` — нууц үг хэзээ ч буцаахгүй   |
| `integrations/qpay/qpay.client.ts`     | HTTP, **§2.1-ийн токен**, халхлалт, алдааны нэг төрөл |
| `integrations/qpay/qpay.schemas.ts`    | Zod. QPay-ийн талбарын нэр энэ хавтаснаас гарахгүй    |
| `integrations/qpay/qpay.service.ts`    | `createInvoice`, `checkPayment`, `paymentsForInvoice` |
| `invoices/qpay-payments.service.ts`    | §2.2-ын гурван алхам, PENDING → PAID, audit           |
| `invoices/qpay-payments.controller.ts` | Гурван route, доорх хүснэгт                           |

| Route                                 | Эрх                  | Тайлбар                          |
| ------------------------------------- | -------------------- | -------------------------------- |
| `POST /v1/invoices/:id/qpay`          | Эцэг эх эсвэл санхүү | QR/deeplink үүсгэнэ              |
| `POST /v1/invoices/:id/qpay/sync`     | Эцэг эх эсвэл санхүү | "Төлсөн ч харагдахгүй байна"     |
| `POST GET /v1/payments/qpay/callback` | **`@Public()`**      | QPay дуудна — доорх ★-ыг үзнэ үү |

★ Callback нь `@Public()` байх ёстой цөөн route-ийн нэг тул: хүсэлтийн
хязгаарлалттай (240/мин), **үргэлж 200 буцаана** (QPay алдааг дахин илгээдэг,
мөн ялгаатай хариу нь ямар payment id бодит болохыг мэдэх суваг болно), бөгөөд
**биедээ огт итгэхгүй**.

**Эцэг эхийн дэлгэц** (`apps/web`):

| Зам                       | Юу харагдах                                       |
| ------------------------- | ------------------------------------------------- |
| Нүүрний **Санхүү** хавтан | `ComingSoonTile` байсныг жинхэнэ холбоос болгов   |
| `/children/:id/invoices`  | Төлөх үлдэгдэл, сар бүрийн нэхэмжлэл              |
| `/invoices/:id`           | Задаргаа, төлбөрийн түүх, **QPay-ээр төлөх** товч |
| `components/finance/`     | `money.ts`, `invoice-card.tsx`, `qpay-dialog.tsx` |

★ **Банкны холбоос эхэнд, QR хоёрдугаарт.** Эцэг эх QR-ийг харуулж буй яг тэр
утсаа барьж байгаа тул түүгээрээ уншуулах боломжгүй — товч дарахад банкны апп
шууд нээгдэнэ. QR нь хоёр дахь төхөөрөмжид зориулсан.

★★ **Polling байхгүй.** Callback хэдхэн секундэд нэхэмжлэлийг хаадаг ч алдагдаж
болзошгүй тул эцэг эхэд **"Төлснөө шалгах"** товч өгсөн (`/qpay/sync`). Хоёр
секунд тутам шалгавал QPay-г манай хязгаарлагчаар дамжуулан цохих ба таб
далд байхад ч ажилласаар байна.

### 4.1 Аюулгүй байдлын тестүүд — `test/qpay-payments.test.ts`

Дараах довтолгоонуудыг тест барьдаг:

## 6. Тодруулах шаардлагатай

| #   | Асуулт                                       | Байдал                                                                                                              |
| --- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 1   | **Sandbox орчин байгаа юу?**                 | ⏳ Мэдэгдэхгүй. Хилийг хуурамч сервертэй бүрэн тестэлсэн; бодит холболтыг **бага дүнгээр нэг удаа** шалгах хэрэгтэй |
| 2   | Нэг мерчант үү, цэцэрлэг бүр өөрийнх үү?     | ✅ **Хариулагдсан 2026-08-31: нэг мерчант бүгдэд нь.** Тиймээс `QPAY_*` нь орчны хувьсагч, схемд талбар нэмээгүй    |
| 3   | Callback URL-ыг QPay-д хэдийд бүртгүүлэх вэ? | ⏳ Production домэйн тодорхой болсны дараа. `QPAY_CALLBACK_URL` заавал **https** байх (`env.ts` шалгана)            |

★ №2-ын хариу нь кодод шууд туссан: `QpayConfig`-д цэцэрлэгээр хайх логик
байхгүй, `QpayService`-ийн ямар ч метод `kindergartenId` авдаггүй. Төлбөр аль
цэцэрлэгийнх болохыг **нэхэмжлэл** нь хэлнэ (`Payment.invoiceId` →
`Invoice.kindergartenId`), итгэмжлэл биш. Хэрэв ирээдүйд цэцэрлэг бүр өөрийн
мерчанттай болвол `QpayConfig` хүснэгтээс уншдаг болно — хоёр дахь багц
хувьсагч нэмж нэг тохиолдлыг тусгайлан шийдэхгүй.

## 7. Ажиллуулахын өмнө

`.env`-д таван утга (`.env.example`-ийн QPay хэсгийг үзнэ үү):

```
QPAY_BASE_URL=https://merchant.qpay.mn/v2
QPAY_USERNAME=…        # QPay-ээс ирсэн клиент нэр
QPAY_PASSWORD=…        # QPay-ээс ирсэн нууц үг — ЗӨВХӨН энд
QPAY_INVOICE_CODE=NOMADKIDS_INVOICE
QPAY_CALLBACK_URL=https://…/v1/payments/qpay/callback
```

★ Тавуулаа эсвэл нэг нь ч биш. Хагас тохируулбал production дээр **ачаалахдаа
татгалзана** (`env.ts`) — учир нь хагас тохируулга нь тохируулсан мэт харагдаад
эцэг эх төлөх гэж оролдох үед л мэдэгддэг.
