## 3. Дууссан ажил

### Spec №1 — дамжуулах схем ба регистрийн дугаар

`docs/superpowers/specs/2026-09-15-esis-full-coverage-design.md` §3, §4
`docs/superpowers/plans/2026-09-15-esis-passthrough-and-register-numbers.md`

- **Гараар бичсэн схем одоо онцгой тохиолдол.** TypeScript код талбарын нэрийг
  нь уншдаг **долоон** уншигчид л үлдсэн; бусад нь `esisDiscoveredSchema`-аар
  ЭСИС-ийн илгээснийг хэвээр дамжуулна. Хил нь **тестээр тогтоогдсон**.
- **РД нэвтэрсэн, хаалттайгаар.** `civilId`/`personRegNumber` задлах хилийг
  давах боловч зөвхөн **тухайн цэцэрлэгийн ADMIN**-д хүрнэ
  (`EsisAdminService.visibleRows`). Нууц үг (`ESIS_DESTROYED_FIELDS`) хэнд ч
  хэзээ ч хүрэхгүй — хил дээр устгагдана.
- **Хоосон биеийн хамгаалалт гурван parser-т** — `esisListParser`,
  `esisCheckParser`, `esisContactsParser`. Тус бүр өөрийн envelope барьдаг тул
  засвар тархдаггүй.

### Spec №2 — ажилтны өөрөө бүртгүүлэх

`docs/superpowers/plans/2026-09-16-esis-staff-self-registration.md`

Багш **цэцэрлэгийн код + РД**-гээр өөрөө бүртгүүлнэ. Захирал батлахгүй, хянана.

- Маршрут нь **нэвтрээгүй хүнд нээлттэй** тул ЭСИС рүү **хэзээ ч хандахгүй** —
  ADMIN-ы дүүргэсэн `EsisStaffRoster`-ыг уншина. Roster хоосон эсвэл 30 хоногоос
  хуучин бол **татгалзана**, амьд дуудлага руу унахгүй.
- **Бүх татгалзал байт-байтаараа ижил** — код буруу, roster-т байхгүй, хэлбэр
  буруу, үүрэг өгөгддөггүй jobCode, аль хэдийн бүртгэлтэй. Амьдаар батлагдсан.
- Үүрэг нь **`jobCode`** (ISCO-08)-оос гарна, `positionName`-ээс биш.
  `5153` (жижүүр) ба `1341` (эрхлэгч) **зориудаар** үүрэг өгөхгүй.

### Spec №3а — sync давхаргууд (унших тал)

`docs/superpowers/plans/2026-09-16-esis-sync-tiers.md`

| Давхарга | Юу                                 | Хэзээ                                                      |
| -------- | ---------------------------------- | ---------------------------------------------------------- |
| 1        | 13 лавлах нөөц → `EsisReference`   | сард (`10 4 1 * *`)                                        |
| 2        | ажилтны roster + шилжилт хөдөлгөөн | өдөрт (`40 3 * * *`)                                       |
| 3        | хүүхэд тус бүрийн уншилт           | **зөвхөн дэлгэц нээхэд**, `assertCanReadEsisChild` + audit |

- Гурвуулангийн дээр ADMIN-ы **гараар «Татах»**, ижил код, ижил `EsisSyncRun`.
- **Дэлгэцүүд хадгалсан хуулбараас уншина.** Хоосон сан `NOT_SYNCED` гэж хэлнэ —
  амьд руу унах зам **байхгүй**, зориудаар.

## 5. Яамнаас олдсон зүйлс — баримтаас биш, амьд хэмжилтээс

Эдгээр нь дахин олдохгүй, тиймээс энд бичигдэв.

1. **`school/staff` нь РД-г жижиг үсгээр илгээдэг** — 13-аас 0 нь загварт
   тохирдог, том үсэг болгоход 13/13. `teacher/list` нь яг тэр хүмүүсийг том
   үсгээр илгээнэ. Roster нь `school/staff`-аас баригддаг тул **хэвийн болгосон
   утгыг хадгална**.
2. **`teacher/list` нэг хүнийг давхардуулдаг** — 10 мөр, 9 ялгаатай `personId`,
   ялгаа нь зөвхөн `username`. Тэндээс roster барихад unique зөрчигдөнө.
3. **`civilId` нь тоо, `personRegNumber` нь мөр** — бүх сервис дээр. Монгол
   регистр үсэг агуулдаг тул тоо болж чадахгүй; энэ тэгш бус байдал жинхэнэ.
4. **119 (мэргэшлийн зэрэг) — эрхийн бүртгэл ба gateway зөрчилдөж байна.**
   Портал `APPROVED` гэж харуулдаг; экспортын зам `/svc/api/zereg/` нь `404`
   (байхгүй), стандарт үндэс дээрх ижил сегмент нь **`403`** (маршрут бодитой,
   token татгалзсан). **Яамтай ярих зүйл.**
5. **186 (MOF барилга)** — хаалттай орлуулагч нь баримтын хэв маяг байсан,
   дүрэм биш. Стандарт үндсээр ажиллана. Гэхдээ байгууллагын регистрийн
   дугаарыг **энэ системд хаана ч хадгалдаггүй** тул operator бичнэ.

## 6. Одоо юу үлдсэн

### (a) Шийдэгдэж буй: синк самбарын байрлал

Самбар `/platform/[id]/esis` дээр байсан (`RequireSuperAdmin`), харин маршрутууд
`@Roles("ADMIN")` — **гишүүнчлэл** шаардана. DB дээр `superadmin` нь
гишүүнчлэлгүй тул товчоо ажиллуулж чадахгүй байв.

Захиалагчийн 2026-09-14-ний дүрэм шийдэв: **«системийн зүйл» superadmin дээр,
«ажлын гадаргуу» цэцэрлэг дээр.** Синк бол ажлын гадаргуу — тэр цэцэрлэгийн
roster-ыг шинэчилж, түүний token-ыг зарцуулна. Тиймээс **самбар `/admin`
руу зөөгдөж байна**, API өөрчлөгдөхгүй.

### (b) Spec №3б — долоон бичих сервис

`150, 152, 162` (бүлэг үүсгэх/засах/багш тохируулах), `129, 131` (хоолны маягт),
`73` (өрх), `72` (цол). Бүгд **бэлтгэх → батлах → илгээх**.

⚠️ Тест орчин байхгүй тул `POST` бүр бодит бичлэг рүү очно. Бүлэг **устгах**
(152) нь буцаах аргагүй. Тусдаа төлөвлөгөө шаардана.

### (c) Spec №4 — яаманд өгөх 84/84 матриц

Сервис бүрийн зорилго, өдөөгч, сүүлд дуудсан огноо, дуудлагын тоо —
`AuditLog` болон `EsisSyncRun`-аас. «Бүгдийг ашигласан» бас «илүүдэл дуудлага
байхгүй» хоёуланг нэг цаасан дээр нотлоно.

## 7. Ажиллах орчны хатуу дүрмүүд

Эдгээрийг зөрчихөд **хуурамч уналт** гарч, аюулгүй байдлын согог мэт харагдана.

- **Хоёр vitest процессыг хэзээ ч зэрэг ажиллуулахгүй.** `beforeEach →
resetData → emptyEveryTable` дээр Postgres `40P01 deadlock` гарч, тухайн
  файлын бүх тест уначихна.
- **`pnpm dev` ажиллаж байхад бүтэн suite ажиллуулахгүй** — ижил үр дагавар.
- **api ба web suite-ыг зэрэг ажиллуулахгүй.**
- Уналт гарвал **эхлээд `beforeEach`-д байгаа эсэхийг хар.** `beforeEach`-д
  унасан цэцэрлэг хоорондын эрхийн тест нь эрхийг **огт шалгаагүй**; биендээ
  унасан нь жинхэнэ задаргаа байж болно. Хураангуй мөрөнд ижил харагдана.
- Миграци: **`prisma migrate deploy`**, хэзээ ч `migrate dev` биш. Түүх
  зөрүүтэй тул RESET санал болгодог — 94 жинхэнэ хүүхэд устана.
- Эдгээр файлууд HEAD дээр prettier-цэвэр биш, **бүү форматла**:
  `esis.catalog.ts`, `esis.fields.ts`, `esis.fields.test.ts`, `esis.service.ts`,
  `apps/web/components/esis/esis-pull-button.tsx`.
