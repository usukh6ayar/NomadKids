# ESIS_API_READINESS.md — Аль API-г яг одоо дуудаж болох вэ

**Асуулт:** «БСМС (ESIS)-ийн ямар ямар API-уудыг шууд ашиглахад бэлэн байна вэ,
яаж ашиглах вэ?»

**Богино хариу:** **Одоогоор нэг ч ESIS endpoint дуудагдахгүй.** Бэлэн зүйл нь
_endpoint_ биш, _холболтын хил_ — тохиргоо, танилт, timeout, алдааны ангилал,
лог, нууц үгийн халхлалт, тест. Токен ирсэн өдөр гурван орчны хувьсагч
бөглөөд л жинхэнэ дуудлага хийж эхэлнэ, код өөрчлөх шаардлагагүй.

★ **Энэ бол дутагдал биш, зориудын шийдвэр.** Бид ESIS-ийн API баримт бичгийг
хараагүй. Хараагүй байж `syncChildren()`, `fetchInstitution()` гэх мэт метод
бичих гэдэг нь **зохиосон endpoint дээр зохиосон схем** барина гэсэн үг.
Тэрхүү метод үүсмэгц түүн дээр дэлгэц баригдаж, таамаг нь кодоор тархана. Тэр
өдөр жинхэнэ гэрээ ирэхэд алдааны өртөг нь нэг файл биш, бүх системд тархсан
байна.

> **Хэлний тухай.** CLAUDE.md-ийн дүрмээр баримт англиар бичигдэнэ. Энэ файл
> `ESIS_COMPLIANCE.md`-тэй ижил зориудын үл хамаарах тохиолдол: яамны талтай
> хамтран уншихаар зориулагдсан. Кодын нэр, файлын зам англиар хэвээр.

---

## 1. Яагаад нэг ч endpoint байхгүй байна вэ — гурван хаалт

| №   | Хаалт                                                            | Хэн онгойлгох вэ     | Төлөв          |
| --- | ---------------------------------------------------------------- | -------------------- | -------------- |
| 1   | **API баримт бичиг** — endpoint, verb, талбарын нэр, жишээ хариу | БМТТ                 | ✗ аваагүй      |
| 2   | **Мэдээлэл солилцох гэрээ** (журам А/465 §3.5)                   | Яам ↔ бид            | ✗ байгуулаагүй |
| 3   | **TOKEN** (журам А/465 §3.7)                                     | БМТТ, гэрээний дараа | ✗ аваагүй      |

Гурав нь дараалсан гинж: гэрээгүйгээр токен байхгүй, токенгүйгээр дуудлага
байхгүй. `docs/ESIS_COMPLIANCE.md` §1-д энэ гинжийг бүрэн тайлбарласан.

★ **Токен яаж ирэх вэ** (БМТТ-ийн «TOKEN авах заавар»): гэрээ байгуулсны дараа
систем нэвтрэх нэр, нууц үгийг автоматаар үүсгэж байгууллагын цахим шуудан руу
`info.edu.mn`-ээс илгээнэ. `developerv2.esis.edu.mn` рүү нэвтэрч
**ACCESS_TOKEN** болон **ENTRY_SOURCE_ID**-г харна. Энэ нь урт хугацааны нэг
токен — `login` урсгал биш.

## 2. Юу нь бэлэн вэ — хилийн бүрэн жагсаалт

Файлууд: `apps/api/src/integrations/esis/`

| Файл                  | Мөр | Юу хийдэг                                                                      |
| --------------------- | --: | ------------------------------------------------------------------------------ |
| `esis.config.ts`      |  80 | Гурван тохиргоог уншиж, «холбогдох боломжтой юу» гэдгийг ганц газраас хариулна |
| `esis.client.ts`      | 246 | HTTP дуудлага: Bearer танилт, timeout, алдааны ангилал, лог, токен халхлалт    |
| `esis.types.ts`       |  78 | Хүсэлт/хариултын **дугтуй**. Домэйн төрөл зориуд байхгүй                       |
| `esis.service.ts`     |  76 | Аппликейшны талын нэвтрэх цэг. Домэйн метод зориуд байхгүй                     |
| `esis.module.ts`      |   — | Ачаалах үед тохиргоог шалгана                                                  |
| `esis.client.test.ts` |   — | Токен алдагдахгүйг батлах сорилууд                                             |

### Аль хэдийн шийдэгдсэн зүйлс

- **Танилт** — токен зөвхөн `Authorization: Bearer` толгойд орно. URL-д, query-д
  хэзээ ч орохгүй (query нь proxy болон access log-д үлддэг).
- **Timeout** — `ESIS_TIMEOUT_MS`, өгөгдмөл 15 000 мс. Хариугүй болсон яамны
  сервер манай хүсэлтийг хязгааргүй барихгүй.
- **Алдааны ангилал** — `not_configured · network · timeout · http ·
invalid_response`. Дуудагч тал нэг `catch` бичээд, `kind`-аар ялгана: timeout
  бол дахин оролдоно, 401 бол операторт мэдэгдэнэ, `invalid_response` бол
  тэдний гэрээ өөрчлөгдсөн — хөгжүүлэгч хэрэгтэй.
- **Токен халхлалт** — `redact()` нь гарах бүх мөрөөс токеныг арилгана.
  Гурван давхар хамгаалалт: (1) URL-д хэзээ ч орохгүй, (2) толгойг лог хийхгүй,
  (3) `redact()` нь мөр бүрийг цэвэрлэнэ.
- **Ил тод байдал** — `GET /v1/health/readiness` нь `esis` хэсгийг буцаана.

★★ **`EsisError` нь `HttpException` биш.** Хэрэв тийм байсан бол ESIS-ийн 401 нь
манай хэрэглэгч рүү шууд дамжиж, нэвтэрсэн администраторт «таны session
хүчингүй» гэж хэлэх байсан. Гадагш чиглэсэн алдаа нь дотогшоо орж ирсэн хүний
статус болж хувирах ёсгүй.

## 3. Бэлэн байдлыг **яг одоо** үзүүлэх арга

Энэ бол БМТТ-д «хил залгагдсан» гэдгээ харуулах бодит нотолгоо.

```bash
# ADMIN эрхээр нэвтэрсэн cookie-тэй
curl -s -b cookies.txt https://api.nomadkids.mn/v1/health/readiness | jq .esis
```

Одоогийн бодит хариу (2026-09-02, production):

```json
{
  "configured": false,
  "baseUrl": "",
  "institutionId": "",
  "hasToken": false
}
```

Токен суусны дараа **ижил дуудлага** дараах байдлаар хариулна:

```json
{
  "configured": true,
  "baseUrl": "https://developerv2.esis.edu.mn",
  "institutionId": "<ENTRY_SOURCE_ID>",
  "hasToken": true
}
```

★ **`hasToken` нь `true`/`false` л буцаана — уртыг нь ч, эхний тэмдэгтийг ч
хэзээ ч биш.** Урт нь brute-force-ын хайлтыг нарийсгана; JWT-ийн эхний хэсэг нь
алгоритмаа нэрлэдэг. Аль аль нь оношилгооны хувьд үнэ цэнэгүй, эрсдэлийн хувьд
бодитой.

## 4. Токен ирсэн өдөр — яг юу хийх вэ

### 4.1 Тохиргоо (код өөрчлөхгүй)

`/opt/nomadkids/.env.production` дээр:

```bash
ESIS_BASE_URL=https://developerv2.esis.edu.mn
ESIS_TOKEN=<БМТТ-ээс ирсэн ACCESS_TOKEN>
ESIS_INSTITUTION_ID=<ENTRY_SOURCE_ID>
ESIS_TIMEOUT_MS=15000
```

Дараа нь **заавал**:

```bash
docker compose -f docker-compose.prod.yml up -d --force-recreate api
```

⚠ `up -d --build` **хангалтгүй**. Compose нь `env_file`-ийн агуулга өөрчлөгдсөнийг
үргэлж хардаггүй — `docs/VPS_DEPLOYMENT.md` §3-д бүртгэсэн бодит тохиолдол.

★★ **Гурвуулаа эсвэл огт үгүй.** Хагас тохируулсан бол production-д ачаалах үед
**татгалзана** (`config/env.ts`). Учир нь хагас тохиргоо нь тохируулсан мэт
харагдаад, дараа нь яамнаас ирэх 401 болж хувирдаг — өөрөөр хэлбэл манай
тохиргооны алдаа нь тэдний танилтын алдаа мэт харагдана.

### 4.2 Эхний бодит дуудлага

`EsisService.request` нь ерөнхий тул баримт бичиг ирмэгц шууд хэрэглэж болно:

```ts
const { data, status, durationMs } = await this.esis.request({
  path: "/api/institution/students",
  method: "GET",
  query: { entrySourceId: this.config.institutionId, page: 1 },
  // ★ parse нь заавал. Ирсэн payload нь энэ хилээс цааш орохоос өмнө
  //   шалгагдана — гурван давхар доор биш, яг энд унана.
  parse: esisStudentPageSchema.parse,
});
```

### 4.3 Эхний жинхэнэ боломжийг нэмэх дараалал

`esis.service.ts`-ийн доод талд бичсэн дараалал, энд давтав:

1. **Баримт бичгийг ав.** Endpoint, verb, танилтын арга, **бодит хариултын
   жишээ**-г кодоос өмнө `docs/`-д бүртгэ.
2. **Zod схем зарла** — `esis.schemas.ts`, энэ хавтас дотор. ESIS-ийн талбарын
   нэрийг энэ хавтаснаас гадна хэн ч мэдэх ёсгүй.
3. **Домэйн метод нэм** — `this.client.request({ parse })` дуудаад **манай**
   домэйн төрлийг буцаа, тэднийхийг биш. Хөрвүүлэлт нь хил дээр байвал тэдний
   талбарын нэр солигдоход нэг файлын засвар болно.
4. **Гадаад ID-ийн асуудлыг тэр үед шийд**, одоо биш — `нэмэлт.md` §15 нь эх
   сурвалж, импортын огноо, импортлосон хэрэглэгч, лавлах id, анхны утга гэсэн
   таван зүйл асуудаг. Энэ бол **багана биш, хүснэгт**, таамаг дээр зохиох
   ёсгүй.
5. **Синхрончлол нь BullMQ дээр**, хүсэлт дотор хэзээ ч биш (CLAUDE.md §6).

## 5. Бид ESIS-ээс юу авахыг, юуг илгээхийг хүсэж байгаа вэ

Дэлгэрэнгүй нь `docs/ESIS_REQUEST.md` Хавсралт 1-д. Товчхон:

### Авах (унших)

- Байгууллагын үндсэн мэдээлэл (§1 #3)
- Хүүхдийн үндсэн мэдээлэл — овог, нэр, төрсөн огноо, хүйс (§1 #5)
- Багш, ажилтны үндсэн мэдээлэл (§1 #7, #51)
- **Нэгдсэн хоолны лавлах** (§1 #37) — А/261-ийн зайлшгүй шалгуур, гэрээгээр хаагдсан

### Өгөх (бичих)

Журам А/465 **§3.17** нь «анхан шатны бүртгэлийн мэдээллийг **бодит цагийн
горимоор хүргүүлнэ**» гэж үүрэг болгосон. Тиймээс хоёр талын солилцоо нь бидний
сонголт биш:

- Хүүхдийн бүртгэл, шилжилт хөдөлгөөн
- Өдөр тутмын ирц (журам §7.3)
- Багш, ажилтны нэмэлт мэдээлэл (§1 #51)

### Зориуд **хүсэхгүй** байгаа зүйлс

Регистрийн дугаарыг ESIS-ээс автоматаар татахгүй (`ESIS_REQUEST.md` §1.1,
хувилбар «b»). Талбар нь схемд байгаа, цэцэрлэг өөрөө бөглөнө. Шаардлагагүй
хувийн мэдээллийг татахгүй байх нь хамгийн хямд хамгаалалт.

## 6. Ойлгомжтой байх ёстой ялгаа

| Асуулт                           | Хариу                                                                                               |
| -------------------------------- | --------------------------------------------------------------------------------------------------- |
| ESIS-ийн API дуудагдаж байна уу? | **Үгүй.** Токен, гэрээ хоёулаа байхгүй                                                              |
| Код бэлэн үү?                    | **Тийм** — хил бүрэн, тесттэй, production-д ачаалагдсан                                             |
| Токен ирвэл хэр удах вэ?         | Тохиргоо нь **минутын** ажил. Эхний endpoint нь баримт бичгээс хамаарч **өдрийн** ажил              |
| Одоо юу үзүүлж болох вэ?         | `/health/readiness`-ийн `esis` хэсэг, энэ баримт, `ESIS_COMPLIANCE.md`-ийн 94 мөрийн өөрийн үнэлгээ |
| Хэн юу хүлээж байна вэ?          | Бид → гэрээ, токен. Яам → §3.18-аар ашиглахаас **3 сарын өмнө** төлөвлөлт батална                   |

★ Сүүлийн мөр нь төлөвлөлтөд шууд нөлөөлнө: журам А/465 §3.18 нь БМТТ
туршилтын хувилбарыг **ашиглахаас 1 сарын өмнө** гаргана гэж заасан. Өөрөөр
хэлбэл sandbox **байдаг**, харин эхний бодит ESIS боломж хэзээ ажиллах нь
гэрээний огноо дээр гурван сар нэмсэн тоо юм.
